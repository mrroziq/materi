BAGIAN XV / DATA SCIENCE

Data Engineering dan Big Data

Data engineering adalah bidang yang berfokus pada pembangunan sistem untuk mengumpulkan, menyimpan, memproses, dan menyediakan data agar siap digunakan untuk analisis maupun machine learning. Dalam skala besar, proses ini melibatkan teknologi big data, data pipeline, sistem terdistribusi, serta pemantauan kualitas data.

1. Konsep ETL dan ELT

ETL dan ELT merupakan dua pendekatan untuk memindahkan data dari sumber ke sistem penyimpanan atau analisis. Perbedaan utamanya terletak pada kapan transformasi data dilakukan.

ETL (Extract, Transform, Load)

  1. Extract: mengambil data dari sumber, seperti database, API, atau file.
  2. Transform: membersihkan dan mengubah data ke format yang dibutuhkan.
  3. Load: memasukkan data hasil transformasi ke sistem tujuan.

ELT (Extract, Load, Transform)

  1. Extract: mengambil data dari sumber.
  2. Load: menyimpan data ke sistem tujuan terlebih dahulu.
  3. Transform: mengolah data di dalam sistem tujuan sesuai kebutuhan analisis.

ETL sering digunakan ketika data perlu dibersihkan sebelum masuk ke sistem tujuan. ELT banyak digunakan pada platform penyimpanan modern yang mampu melakukan transformasi secara efisien di dalam sistemnya.

Contoh proses sederhana ETL menggunakan Pandas:

import pandas as pd

# Extract
df = pd.read_csv("transaksi.csv")

# Transform
df = df.drop_duplicates()
df["total"] = df["harga"] * df["jumlah"]
df = df.dropna(subset=["harga", "jumlah"])

# Load
df.to_csv("transaksi_bersih.csv", index=False)

print("Jumlah baris hasil:", len(df))

Pada contoh ini, data dibaca dari CSV, dibersihkan, dibuatkan kolom total, lalu disimpan kembali ke CSV. Dalam sistem produksi, tahap load dapat berupa penyimpanan ke database, data warehouse, atau data lake.

2. Data Warehouse dan Data Lake

Data warehouse dan data lake merupakan dua pendekatan penyimpanan data yang memiliki tujuan dan karakteristik berbeda.

Data Warehouse

Data warehouse dirancang untuk menyimpan data yang terstruktur dan telah diorganisasikan agar mudah digunakan dalam pelaporan, business intelligence, serta analisis historis.

  • Biasanya menggunakan skema data yang jelas.
  • Mendukung kueri analitis dan agregasi.
  • Sering menyimpan data dari berbagai sistem operasional.

Data Lake

Data lake menyimpan data dalam berbagai bentuk, termasuk data terstruktur, semi-terstruktur, dan tidak terstruktur. Data dapat disimpan sebelum seluruh kebutuhan transformasinya diketahui.

  • Dapat menyimpan CSV, JSON, Parquet, gambar, log, dan data lainnya.
  • Cocok untuk eksplorasi data, machine learning, dan pemrosesan skala besar.
  • Membutuhkan pengelolaan metadata, kualitas, keamanan, dan tata kelola data.

Perbandingan ringkas:

Aspek Data Warehouse Data Lake
Jenis data Umumnya terstruktur Terstruktur hingga tidak terstruktur
Skema Biasanya ditentukan sebelum analisis Dapat ditentukan saat data digunakan
Penggunaan Pelaporan dan analisis bisnis Eksplorasi, analitik, dan machine learning
Pengelolaan Fokus pada struktur dan konsistensi analitis Fokus pada fleksibilitas sekaligus tata kelola

Keduanya tidak selalu saling menggantikan. Organisasi dapat menggunakan data lake untuk menyimpan data mentah dan data warehouse untuk menyediakan data terkurasi bagi pelaporan.

3. Pemrosesan Data Batch dan Streaming

Data dapat diproses sekaligus dalam kumpulan atau diproses secara berkelanjutan ketika data baru masuk.

Batch Processing

Batch processing mengolah sekumpulan data dalam satu proses terjadwal. Contohnya adalah menghitung total transaksi setiap malam atau membuat laporan penjualan bulanan.

Stream Processing

Stream processing mengolah data yang datang secara berkelanjutan. Contohnya adalah mendeteksi transaksi mencurigakan, memantau sensor, atau memperbarui metrik operasional secara mendekati waktu nyata.

Aspek Batch Streaming
Pola pemrosesan Kumpulan data Aliran data berkelanjutan
Latensi Menit, jam, atau lebih Dapat sangat rendah
Contoh Laporan harian Monitoring sensor

Contoh batch processing untuk menghitung total penjualan harian:

import pandas as pd

df = pd.read_csv("transaksi.csv")
df["waktu"] = pd.to_datetime(df["waktu"])

df["tanggal"] = df["waktu"].dt.date

ringkasan = (
    df.groupby("tanggal", as_index=False)
    .agg(total_penjualan=("nilai_transaksi", "sum"))
)

ringkasan.to_csv("penjualan_harian.csv", index=False)

print(ringkasan)

Batch dan streaming dapat digunakan bersama. Misalnya, sistem menyimpan transaksi sebagai aliran data, kemudian membuat ringkasan harian melalui pemrosesan batch.

4. Format Data CSV, JSON, dan Parquet

Format penyimpanan memengaruhi ukuran file, struktur data, kecepatan baca, dan kemudahan pertukaran data.

CSV

CSV menyimpan data tabular sebagai teks dengan pemisah antarkolom. Format ini mudah dibaca manusia dan didukung oleh hampir semua alat analisis, tetapi tidak menyimpan tipe data kolom secara eksplisit. 

import pandas as pd

df = pd.read_csv("data.csv")
df.to_csv("hasil.csv", index=False)

JSON

JSON mendukung struktur data berupa objek, array, string, angka, boolean, dan nilai null. Format ini banyak digunakan pada API dan pertukaran data antaraplikasi. 

import pandas as pd

df = pd.read_json("data.json")
df.to_json("hasil.json", orient="records", indent=2)

Jika JSON berisi objek bersarang, struktur tersebut mungkin perlu diratakan menggunakan pd.json_normalize().

Parquet

Parquet adalah format penyimpanan kolumnar yang menyimpan informasi tipe data dan mendukung kompresi. Format ini sering cocok untuk analisis data berukuran besar karena kueri dapat membaca kolom yang diperlukan saja. 

import pandas as pd

df = pd.read_csv("data.csv")

df.to_parquet("data.parquet", index=False)

data_parquet = pd.read_parquet("data.parquet")

print(data_parquet.head())

Pembacaan dan penulisan Parquet pada Pandas memerlukan mesin pendukung, misalnya pyarrow atau fastparquet.

Format Kelebihan Penggunaan umum
CSV Sederhana dan mudah dibuka Dataset tabular dan pertukaran data
JSON Mendukung struktur bertingkat API dan aplikasi web
Parquet Kolumnar, bertipe, dan mendukung kompresi Analitik data besar

5. Dasar Apache Spark

Apache Spark adalah mesin pemrosesan data terdistribusi yang dirancang untuk mengolah data dalam skala besar. Spark dapat menjalankan operasi transformasi dan analisis dengan membagi pekerjaan ke beberapa partisi dan mesin.

Beberapa komponen penting Spark meliputi:

  • Spark SQL: memproses data terstruktur menggunakan SQL dan DataFrame.
  • DataFrame: representasi data terstruktur dengan kolom bernama.
  • Transformations: operasi seperti filter, select, dan groupBy.
  • Actions: operasi yang meminta hasil, misalnya count dan collect.
  • Partition: bagian data yang dapat diproses secara paralel.

Contoh menggunakan PySpark

from pyspark.sql import SparkSession
from pyspark.sql.functions import col, sum

spark = (
    SparkSession.builder
    .appName("AnalisisPenjualan")
    .getOrCreate()
)

df = spark.read.csv(
    "transaksi.csv",
    header=True,
    inferSchema=True
)

df.printSchema()

hasil = (
    df.filter(col("jumlah") > 0)
    .groupBy("produk")
    .agg(sum("jumlah").alias("total_jumlah"))
)

hasil.show()

spark.stop()

Contoh tersebut membaca CSV, memfilter transaksi dengan jumlah positif, lalu menghitung total jumlah per produk. Kolom produk dan jumlah harus tersedia pada file.

Spark mendukung eksekusi terdistribusi, tetapi tidak semua pekerjaan otomatis menjadi lebih cepat. Ukuran data, jumlah partisi, biaya komunikasi, dan konfigurasi komputasi tetap memengaruhi performa.

6. Data Pipeline

Data pipeline adalah rangkaian proses otomatis yang memindahkan dan mengolah data dari sumber hingga menjadi keluaran yang siap digunakan.

Contoh alur pipeline:

Sumber Data
    |
    v
Pengambilan Data
    |
    v
Validasi dan Pembersihan
    |
    v
Transformasi
    |
    v
Penyimpanan
    |
    v
Analisis atau Machine Learning

Pipeline yang baik biasanya memiliki karakteristik berikut:

  • Reproducible: proses dapat dijalankan kembali dengan hasil yang dapat ditelusuri.
  • Reliable: kegagalan dapat dideteksi dan ditangani.
  • Idempotent: menjalankan ulang proses tidak menyebabkan duplikasi atau efek samping yang tidak diinginkan.
  • Observable: status, log, metrik, dan kegagalan dapat dipantau.
  • Scalable: proses dapat menyesuaikan diri dengan pertumbuhan data.

Contoh pipeline sederhana

import pandas as pd
from pathlib import Path

def run_pipeline(source, destination):
    df = pd.read_csv(source)

    df.columns = (
        df.columns
        .str.strip()
        .str.lower()
        .str.replace(" ", "_")
    )

    df = df.drop_duplicates()

    required_columns = ["produk", "jumlah", "harga"]

    missing_columns = [
        column
        for column in required_columns
        if column not in df.columns
    ]

    if missing_columns:
        raise ValueError(
            f"Kolom wajib tidak tersedia: {missing_columns}"
        )

    df = df.dropna(
        subset=required_columns
    )

    df["total"] = df["jumlah"] * df["harga"]

    destination = Path(destination)
    destination.parent.mkdir(
        parents=True,
        exist_ok=True
    )

    df.to_csv(destination, index=False)

    return df.shape

hasil = run_pipeline(
    "transaksi.csv",
    "output/transaksi_bersih.csv"
)

print("Ukuran data hasil:", hasil)

Contoh ini memisahkan proses ke dalam fungsi agar dapat digunakan kembali. Pada sistem produksi, pipeline juga perlu menangani skema yang berubah, kegagalan sumber data, pencatatan log, dan mekanisme pemulihan.

7. API dan Pengambilan Data

API (Application Programming Interface) memungkinkan suatu aplikasi meminta atau mengirim data ke sistem lain. REST API sering menggunakan HTTP dan mengembalikan data dalam format JSON.

Metode HTTP yang umum antara lain:

  • GET: mengambil data.
  • POST: mengirim data atau membuat sumber daya.
  • PUT/PATCH: memperbarui data.
  • DELETE: menghapus sumber daya.

Contoh mengambil data dari API

import requests
import pandas as pd

url = "https://jsonplaceholder.typicode.com/posts"

response = requests.get(
    url,
    timeout=15
)

response.raise_for_status()

data = response.json()

df = pd.DataFrame(data)

print(df.head())
df.to_csv("posts.csv", index=False)

Contoh tersebut menggunakan API publik untuk demonstrasi. Pada proyek nyata, pastikan penggunaan API sesuai ketentuan penyedia layanan, batas permintaan, autentikasi, dan kebijakan privasi.

Hal yang perlu diperhatikan

  • Gunakan timeout agar permintaan tidak menunggu tanpa batas.
  • Periksa kode status HTTP melalui raise_for_status().
  • Tangani pagination jika hasil dibagi ke beberapa halaman.
  • Jangan menaruh API key atau token rahasia langsung di kode yang dibagikan.
  • Tambahkan retry dengan jeda yang sesuai untuk kegagalan sementara.

8. Orkestrasi Workflow

Orkestrasi workflow adalah proses mengatur urutan pelaksanaan tugas, jadwal, dependensi, percobaan ulang, serta penanganan kegagalan dalam sebuah pipeline.

Misalnya, pipeline analisis penjualan membutuhkan beberapa tugas:

  1. Mengambil data transaksi.
  2. Memvalidasi dan membersihkan data.
  3. Menghitung ringkasan penjualan.
  4. Menyimpan hasil analisis.
  5. Mengirim notifikasi jika proses selesai atau gagal.

Tugas pembersihan tidak seharusnya berjalan sebelum pengambilan data selesai. Orkestrator mengelola ketergantungan semacam ini.

Contoh orkestrasi menggunakan Apache Airflow

from datetime import datetime

from airflow import DAG
from airflow.operators.bash import BashOperator

with DAG(
    dag_id="pipeline_penjualan",
    start_date=datetime(2026, 1, 1),
    schedule="@daily",
    catchup=False
) as dag:

    extract = BashOperator(
        task_id="extract_data",
        bash_command="python extract.py"
    )

    transform = BashOperator(
        task_id="transform_data",
        bash_command="python transform.py"
    )

    load = BashOperator(
        task_id="load_data",
        bash_command="python load.py"
    )

    extract >> transform >> load

Operator Extract, Transform, dan Load pada contoh tersebut menjalankan skrip Python secara berurutan. File skrip yang dipanggil harus tersedia di lingkungan tempat Airflow berjalan.

Airflow memerlukan instalasi dan konfigurasi lingkungan tersendiri. Selain Airflow, terdapat pilihan lain seperti Prefect dan Dagster. Pemilihan alat bergantung pada kompleksitas pipeline, kebutuhan pemantauan, dan lingkungan infrastruktur.

9. Data Quality dan Monitoring

Data quality adalah tingkat kesesuaian data terhadap kebutuhan penggunaan. Data yang buruk dapat menghasilkan laporan yang salah dan model machine learning yang tidak andal.

Dimensi kualitas data yang umum meliputi:

  • Completeness: apakah data penting tersedia?
  • Validity: apakah nilai memenuhi aturan dan tipe yang diharapkan?
  • Consistency: apakah data konsisten antarbagian sistem?
  • Uniqueness: apakah terdapat duplikasi yang tidak semestinya?
  • Timeliness: apakah data tersedia tepat waktu?
  • Accuracy: apakah data merepresentasikan kondisi sebenarnya?

Contoh validasi kualitas data

import pandas as pd

df = pd.read_csv("transaksi.csv")

assert "harga" in df.columns
assert "jumlah" in df.columns

assert df["harga"].notna().all(), (
    "Terdapat harga kosong"
)

assert df["jumlah"].notna().all(), (
    "Terdapat jumlah kosong"
)

assert (df["harga"] >= 0).all(), (
    "Harga tidak boleh negatif"
)

assert (df["jumlah"] >= 0).all(), (
    "Jumlah tidak boleh negatif"
)

print("Validasi dasar berhasil")
print("Jumlah baris:", len(df))
print("Jumlah duplikasi:", df.duplicated().sum())

Pernyataan assert dapat menghentikan program jika kondisi tidak terpenuhi. Pada pipeline produksi, validasi biasanya perlu menghasilkan laporan kegagalan yang terstruktur dan mengirim notifikasi bila diperlukan.

Monitoring pipeline

Monitoring dilakukan untuk memastikan pipeline tetap berjalan dengan benar. Beberapa metrik yang dapat dipantau meliputi:

  • Waktu eksekusi setiap tahap.
  • Jumlah baris yang masuk dan keluar.
  • Persentase nilai kosong dan jumlah duplikasi.
  • Kegagalan tugas dan jumlah percobaan ulang.
  • Keterlambatan kedatangan data.
  • Perubahan distribusi fitur dari waktu ke waktu.

Perubahan distribusi data dapat menjadi indikasi data drift. Namun, data drift tidak selalu berarti performa model langsung memburuk; evaluasi tambahan diperlukan untuk mengetahui dampaknya.

Ringkasan

  • ETL melakukan transformasi sebelum pemuatan, sedangkan ELT melakukan transformasi setelah data dimuat.
  • Data warehouse berorientasi pada analisis data terstruktur, sedangkan data lake mendukung penyimpanan beragam jenis data.
  • Batch memproses kumpulan data, sementara streaming memproses aliran data berkelanjutan.
  • CSV sederhana, JSON mendukung struktur bertingkat, dan Parquet cocok untuk penyimpanan kolumnar analitis.
  • Apache Spark membantu memproses data skala besar secara terdistribusi.
  • Data pipeline menghubungkan tahapan pengambilan, transformasi, dan penyimpanan data.
  • API memungkinkan sistem mengambil dan bertukar data.
  • Orkestrasi mengatur jadwal, urutan tugas, dependensi, dan pemulihan kegagalan.
  • Data quality dan monitoring membantu menjaga keandalan data serta proses pengolahannya.
