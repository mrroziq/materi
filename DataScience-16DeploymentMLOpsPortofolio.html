Deployment, MLOps, dan Portofolio

Model machine learning tidak hanya digunakan untuk menghasilkan prediksi di notebook. Model juga perlu disimpan, diintegrasikan ke aplikasi, diterapkan pada lingkungan produksi, dipantau, dan diperbarui ketika performanya menurun. Proses tersebut berkaitan dengan deployment dan MLOps.

1. Menyimpan dan Memuat Model

Setelah model dilatih dan dievaluasi, model dapat disimpan agar digunakan kembali tanpa harus menjalankan proses pelatihan dari awal. Model beserta preprocessing yang diperlukan sebaiknya dikelola secara konsisten.

Menggunakan Joblib

joblib sering digunakan untuk menyimpan model scikit-learn, terutama model yang melibatkan array NumPy. 

import joblib
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(random_state=42)
model.fit(X_train, y_train)

joblib.dump(model, "model.pkl")

model_loaded = joblib.load("model.pkl")
predictions = model_loaded.predict(X_test)

Menyimpan preprocessing dan model

Jika model menggunakan imputasi, encoding, atau standardisasi, preprocessing tersebut harus diterapkan dengan cara yang sama ketika model digunakan pada data baru. Salah satu pendekatannya adalah menggabungkan preprocessing dan model ke dalam sebuah pipeline. 

import joblib
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])

pipeline.fit(X_train, y_train)

joblib.dump(pipeline, "pipeline_model.pkl")

pipeline_loaded = joblib.load("pipeline_model.pkl")
predictions = pipeline_loaded.predict(X_test)

File model dari sumber yang tidak tepercaya tidak boleh dimuat sembarangan karena format serialisasi tertentu dapat menjalankan kode berbahaya. Versi library dan dependensi model juga perlu dicatat.

2. Membuat API dengan Flask atau FastAPI

API memungkinkan aplikasi lain mengirim data ke model dan menerima hasil prediksi melalui jaringan. Flask dan FastAPI merupakan dua framework Python yang dapat digunakan untuk membangun layanan tersebut.

Contoh API menggunakan Flask

Misalkan model klasifikasi telah disimpan pada file model.pkl. API berikut menerima dua fitur numerik dan mengembalikan hasil prediksi. 

from flask import Flask, request, jsonify
import joblib
import numpy as np

app = Flask(__name__)
model = joblib.load("model.pkl")

@app.route("/predict", methods=["POST"])
def predict():
    data = request.get_json()

    features = np.array([
        data["features"]
    ])

    prediction = model.predict(features)

    return jsonify({
        "prediction": prediction.tolist()
    })

if __name__ == "__main__":
    app.run(debug=True)

Contoh data JSON yang dikirim ke endpoint:

{
    "features": [5.2, 3.1]
}

Jumlah, urutan, dan tipe fitur harus sesuai dengan yang digunakan ketika model dilatih. Dalam aplikasi nyata, tambahkan validasi input, penanganan kesalahan, autentikasi bila diperlukan, serta konfigurasi produksi yang aman.

Flask dan FastAPI

  • Flask: framework ringan dengan struktur sederhana.
  • FastAPI: mendukung validasi data berbasis tipe Python dan dokumentasi API otomatis.

3. Membuat Aplikasi dengan Streamlit

Streamlit memungkinkan pembuatan aplikasi data science interaktif menggunakan Python tanpa harus membangun antarmuka web dari awal. Pengguna dapat memasukkan data, memilih parameter, dan melihat hasil prediksi melalui browser.

Contoh aplikasi prediksi

import streamlit as st
import joblib
import numpy as np

model = joblib.load("model.pkl")

st.title("Aplikasi Prediksi")
st.write("Masukkan nilai fitur untuk menghasilkan prediksi.")

fitur_1 = st.number_input("Fitur 1", value=0.0)
fitur_2 = st.number_input("Fitur 2", value=0.0)

if st.button("Prediksi"):
    data = np.array([[fitur_1, fitur_2]])
    hasil = model.predict(data)

    st.success(f"Hasil prediksi: {hasil[0]}")

Simpan kode tersebut sebagai app.py, kemudian jalankan:

streamlit run app.py

Aplikasi ini dapat dikembangkan dengan fitur unggah CSV, visualisasi data, perbandingan model, dan unduhan hasil prediksi.

4. Deployment Aplikasi

Deployment adalah proses menempatkan aplikasi agar dapat dijalankan oleh pengguna di lingkungan yang dituju. Aplikasi dapat dijalankan secara lokal, pada server, atau melalui layanan cloud.

Alur deployment

  1. Pastikan model telah dievaluasi dan siap digunakan.
  2. Siapkan kode aplikasi dan file dependensi.
  3. Uji aplikasi di lingkungan lokal.
  4. Konfigurasikan server atau platform hosting.
  5. Jalankan aplikasi dan uji endpoint atau antarmukanya.
  6. Pantau log, penggunaan sumber daya, dan kesalahan aplikasi.

Mencatat dependensi

File requirements.txt mencatat library Python yang diperlukan oleh aplikasi. Contohnya: 

flask
streamlit
scikit-learn
pandas
numpy
joblib

Untuk proyek yang dikelola secara serius, gunakan versi dependensi yang teruji agar lingkungan pengembangan dan produksi tetap konsisten. Rahasia seperti API key dan kata sandi tidak boleh ditulis langsung di dalam kode yang dipublikasikan.

5. Git dan GitHub

Git adalah sistem pengendalian versi yang mencatat perubahan kode dari waktu ke waktu. GitHub merupakan platform untuk menyimpan dan mengelola repositori Git secara daring.

Perintah dasar Git

# Inisialisasi repositori
git init

# Melihat perubahan
git status

# Memasukkan perubahan ke staging area
git add .

# Membuat commit
git commit -m "Membuat model prediksi"

# Mengatur branch utama
git branch -M main

# Menambahkan repositori remote
git remote add origin URL_REPOSITORI

# Mengirim perubahan ke GitHub
git push -u origin main

Ganti URL_REPOSITORI dengan alamat repositori milik sendiri. Untuk proyek data science, gunakan .gitignore agar file sementara, lingkungan virtual, data sensitif, dan file berukuran besar yang tidak perlu tidak ikut dimasukkan ke repositori.

Contoh struktur repositori

proyek-data-science/
├── data/
├── notebooks/
├── src/
│   ├── preprocessing.py
│   └── train.py
├── models/
├── app.py
├── requirements.txt
├── README.md
└── .gitignore

6. Experiment Tracking

Experiment tracking adalah proses mencatat eksperimen pelatihan model agar hasil dari berbagai konfigurasi dapat dibandingkan. Informasi yang dicatat dapat meliputi parameter, metrik evaluasi, versi kode, dataset, dan artefak model.

Contoh pencatatan sederhana

import pandas as pd
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import accuracy_score

hasil_eksperimen = []

for jumlah_pohon in [50, 100, 200]:
    model = RandomForestClassifier(
        n_estimators=jumlah_pohon,
        random_state=42
    )

    model.fit(X_train, y_train)
    prediksi = model.predict(X_valid)

    akurasi = accuracy_score(y_valid, prediksi)

    hasil_eksperimen.append({
        "n_estimators": jumlah_pohon,
        "accuracy": akurasi
    })

tabel_hasil = pd.DataFrame(hasil_eksperimen)
print(tabel_hasil.sort_values("accuracy", ascending=False))

Untuk eksperimen yang lebih kompleks, alat seperti MLflow dapat membantu mencatat parameter, metrik, artefak, dan versi model secara terstruktur.

Pemilihan model sebaiknya didasarkan pada metrik yang sesuai dengan tujuan masalah, bukan hanya akurasi. Data validasi digunakan untuk membandingkan konfigurasi, sedangkan data uji sebaiknya tetap menjadi evaluasi akhir yang tidak dipakai berulang kali untuk memilih model.

7. Versioning Dataset dan Model

Versioning adalah pengelolaan versi data dan model sehingga setiap hasil eksperimen dapat ditelusuri kembali. Model yang berbeda mungkin berasal dari dataset, fitur, parameter, atau kode yang berbeda.

Informasi yang perlu dicatat

  • Versi atau identitas dataset yang digunakan.
  • Tanggal pelatihan dan sumber data.
  • Daftar fitur dan langkah preprocessing.
  • Algoritma, hyperparameter, dan random seed.
  • Metrik evaluasi pada data validasi dan data uji.
  • Versi kode serta dependensi.

Dataset berukuran besar dapat dikelola menggunakan alat versioning data seperti DVC. Model juga dapat disimpan dengan identitas versi, misalnya model_v1 dan model_v2, disertai metadata yang menjelaskan proses pembuatannya.

Hindari mengandalkan nama file saja. Catatan metadata diperlukan agar kita mengetahui model mana yang dibuat dari data dan konfigurasi tertentu.

8. Monitoring Performa Model

Performa model setelah deployment dapat berbeda dari hasil evaluasi saat pengembangan. Perubahan pola data atau perilaku pengguna dapat menyebabkan penurunan kualitas prediksi.

Hal yang dipantau

  • Performa prediksi: precision, recall, F1, MAE, atau metrik yang relevan setelah label tersedia.
  • Data drift: perubahan distribusi fitur masukan dibandingkan data pelatihan.
  • Prediction drift: perubahan distribusi keluaran prediksi.
  • Kesehatan layanan: waktu respons, jumlah permintaan, tingkat kesalahan, dan penggunaan sumber daya.
  • Kualitas data: nilai hilang, rentang yang tidak valid, dan perubahan skema.

Data drift tidak selalu berarti performa model menurun. Sebaliknya, perubahan performa juga perlu dianalisis bersama kualitas label, perubahan proses bisnis, dan kondisi data.

9. Retraining Model

Retraining adalah proses melatih ulang model menggunakan data terbaru atau data yang telah diperbarui. Retraining dapat diperlukan ketika model tidak lagi memenuhi target performa atau karakteristik data mengalami perubahan yang berarti.

Alur retraining

  1. Kumpulkan data terbaru yang relevan dan berkualitas.
  2. Validasi data serta periksa potensi data leakage.
  3. Latih model baru dengan prosedur yang terdokumentasi.
  4. Evaluasi model baru menggunakan data validasi yang tepat.
  5. Bandingkan hasilnya dengan model yang sedang digunakan.
  6. Deploy model baru jika memenuhi kriteria penerimaan.
  7. Pantau model setelah pergantian dan siapkan mekanisme rollback.

Retraining tidak harus dilakukan hanya karena data baru tersedia. Jadwal dan pemicunya perlu disesuaikan dengan karakteristik masalah, ketersediaan label, biaya pelatihan, dan risiko kesalahan prediksi. Model baru sebaiknya tidak menggantikan model lama sebelum lolos evaluasi.

10. Dokumentasi Proyek dan Presentasi Hasil

Dokumentasi membantu orang lain memahami tujuan, proses, hasil, keterbatasan, dan cara menjalankan proyek. Dokumentasi yang baik juga menjadi bagian penting dari portofolio data science.

Struktur README

  1. Judul: nama dan gambaran singkat proyek.
  2. Latar belakang: masalah yang ingin diselesaikan.
  3. Tujuan: pertanyaan atau target analisis.
  4. Dataset: sumber, jumlah data, fitur, dan target.
  5. Metodologi: preprocessing, analisis, dan pemodelan.
  6. Evaluasi: metrik, hasil, dan pembanding model.
  7. Deployment: cara menjalankan aplikasi atau API.
  8. Keterbatasan: asumsi, risiko, dan hal yang belum ditangani.
  9. Kesimpulan: temuan dan rencana pengembangan.

Kerangka presentasi

  • Masalah dan alasan proyek dilakukan.
  • Data yang digunakan dan proses pengolahannya.
  • Metode yang dipilih beserta alasannya.
  • Hasil evaluasi menggunakan tabel atau visualisasi.
  • Demo aplikasi atau contoh prediksi.
  • Kesimpulan, keterbatasan, dan pengembangan berikutnya.

Portofolio yang kuat tidak harus menggunakan model paling rumit. Proyek yang menjelaskan masalah dengan jelas, memiliki proses yang dapat direproduksi, mengevaluasi model secara benar, dan menyampaikan hasil secara jujur dapat menunjukkan kemampuan data science dengan baik.

Latihan Mandiri

  1. Latih model klasifikasi sederhana, kemudian simpan dan muat kembali model tersebut.
  2. Buat API dengan endpoint /predict yang menerima data JSON dan mengembalikan prediksi.
  3. Buat aplikasi Streamlit yang menerima input pengguna dan menampilkan hasil prediksi.
  4. Unggah kode proyek ke GitHub dengan README dan requirements.txt.
  5. Bandingkan tiga konfigurasi model dan catat metrik validasinya.
  6. Susun rencana monitoring dan kriteria yang akan digunakan untuk retraining.
  7. Buat presentasi singkat yang menjelaskan masalah, metode, evaluasi, dan keterbatasan proyek.

Ringkasan

Deployment membuat model dapat digunakan oleh pengguna, sedangkan MLOps membantu mengelola siklus hidup model secara sistematis. Penyimpanan model, API, aplikasi interaktif, versioning, experiment tracking, monitoring, retraining, dan dokumentasi saling melengkapi untuk menghasilkan solusi machine learning yang dapat dipelihara.
